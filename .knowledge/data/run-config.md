---
id: data:run-config
type: data
title: Run Config
---
Runtime settings a built artifact reads at startup, covering everything that is not a linkage decision.

```yaml
file: the run sections of ebigent.toml, see decision:one-config-file-many-sections
layers:
  - build: fixed by concept:build-target, not configurable
  - stage: data:session-tuning-profile, the timing and bandwidth constants of one stage, bound per run rather than fixed at build
  - run: this record, chosen per process launch
  - session: per session values arriving in data:session-ticket
run_fields:
  - topology and listen address, checked by rule:unauthenticated-admission-requires-scope-or-capability
  - transport selection by concept:transport-capability
  - synchronization mode, baseline mode, ack mode
  - time_scale of concept:game-time-control, including step and accelerated
  - agent roster: which controller fills each concept:player-slot, which seeds api:roster and may fill it completely so a run never gathers
  - episode logging destination and sampling rate
  - evaluation_version of data:evaluation-signal
  - api:dev-debug-endpoint address, honored only by a development build
binding: generated by system:tinybind config binding, the same mechanism as its other config support
source_precedence: rule:config-precedence-fixed governs which source supplies a field
precedence: session overrides run, run overrides defaults
tuning_must_agree: every peer of one match must bind the same data:session-tuning-profile; netplay refuses to reconstruct state under a profile the server does not run
game_extension: a game binds its own struct under its own prefix in the same file, joining the same env and CLI surface
ignored_by: the ebigent tool, which registers none of these prefixes
authored_by: the dev verb of api:game-cli passes these down as CLI options when running a child process
```
