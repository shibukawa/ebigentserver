# step 1 — マウス1つで交互に指す

```bash
go run ./tutorial/step1-hotseat
```

ebigentserver を一切使わない、ふつうの Ebitengine アプリ。1台のマシンで2人が同じマウスを
使い、交互にセルをクリックする。勝敗が付いたらどこかをクリックすると次の一局が始まる
（`R` キーでも）。

## 構成

```
step1-hotseat/
├── main.go          ウィンドウ・マウス・描画（engine を import する唯一の場所）
└── game/
    ├── game.go      ルール。engine を知らない
    └── game_test.go ルールのテスト。ウィンドウを開かずに走る
```

2パッケージに割ってあるのは作法のためではない。engine を import しないパッケージは
**ウィンドウなしでテストできる**からで、これは CI で走るテストと走らないテストの差になる。
`main.go` の側にテストを置くと、ディスプレイのない Linux では ebiten の初期化で落ちる。

## この形が後で効くところ

- **`cellAt` が入力処理の全部** — ピクセルがセル番号に変わるのはここだけで、この線より下は
  マウスというものを知らない。step2 ではこの関数の出口がそのまま `Submit` の引数になり、
  行き先がローカルの inbox かネットワークのソケットかを、この行は知らないままになる。
- **`game` パッケージが engine を知らない** — step2 で `session.StageRuleSet` を実装するとき、
  移すのではなくメソッドを足すだけで済む。
- **`Place` が不正な手を自分で拒む** — 呼ぶ側は盤上のどこをクリックされても素通しでよい。
  step2 の `ActionValidator` はこの判定をそのまま受け取る。

## まだないもの

ボットも、記録も、ネットワークも、シードもない。`Update` が世界を直接書き換えていて、
tick という概念すらない。ここから何が足りないかは、[step2](../step2-lobby/) で埋まる。
