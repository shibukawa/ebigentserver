席数、ホスト、リンク、シグナリングを組み合わせると、候補はすぐに数十通りになります。
しかし、実際に**相手へ接続できる**構成は、その一部だけです。

## 届く7つ

### solo

1席だけで、ホストはプロセス内にあります。リンクは pipe さえ使わず、agent がそのまま session に
着席します。シグナリングが必要ない唯一の構成です。

### local_loopback

2席以上で、プレイ中のプロセスがホストになります。リンクにはプロセス内の `transport/pipe` を使います。

solo とは異なり、local_loopback では agent と session の**間にトランスポートが入ります**。
ネットワークを使わずに、エンコード、snapshot と delta の生成、シーケンス番号、ack までを
実行できます。

さらに、この pipe には方向ごとに損失、遅延、ジッタ、並べ替えを注入できます。rollback、
lag compensation、delta baseline の復帰経路を、実在しない悪い回線に対して試験するための
試験するための装置です。ドロップと並べ替えのパターンはシードから再現できますが、到着時刻は
実時間のタイマーで決まるため再現しません。

`ebigent dev` は、この構成を使います。

### lan_pair_or_party

2席以上で、プレイ中のプロセスがホストになります。リンクローカルアドレス上の WebTransport または
QUIC-UDP を使い、[LAN ディスカバリ](/connection/signaling/)で相手を見つけます。

ブラウザは UDP ブロードキャストを送れないため、**ネイティブビルド限定**です。

### invited_pair_or_party

2席以上で、プレイ中のプロセスがホストになり、WebRTC を使います。シグナリングには
[手動トークン](/connection/signaling/#手動トークン)——offer と answer をプレイヤー自身が
チャットや掲示板を使います。

静的ファイルだけで実現でき、バックエンドは必要ありません。

### brokered_peer

2席以上で、プレイ中のプロセスがホストになり、WebRTC を使います。シグナリングは control plane が発行する
チケットが担います。サーバはマッチング、認証、シグナリングを行いますが、対局中のデータには触れません。

### central

2席以上で、専用ホストに WebTransport で接続します。利用できない場合は WebSocket へ切り替えます。
サーバはデータ経路にいるため、
プレイヤー間の通信は、すべて2ホップになります。

その代わり、**対局結果をランク戦の成績として信頼できる唯一の構成**です。

### relayed_peer

2席以上で、プレイ中のプロセスがホストになります。TURN リレー経由の WebRTC を使うため、サーバは
データ経路に入りますが、
これは主経路ではなく、ピア同士が直接接続できなかった場合のフォールバックです。

制限の厳しいネットワークでも接続できますが、リレーによるホップ数と帯域コストが増えます。
このコストを負担するのは、リレーが必要になったセッションだけです。

## 届かない3つ

| 構成 | なぜ成立しないか |
|---|---|
| メッシュ | ここでのピアリンクは star 型なので、N ピアは「1ホストと N リンク」であって N² にはならない |
| 主経路としての「dedicated × WebRTC」 | 証明書とルーティング可能な名前を持つホストが NAT 越えから得るものはない。届かないピアの退避路としてなら、それは上の relayed_peer であって別のもの |
| インターネット上の「プレイ中ホスト × WebTransport」 | 証明書と着信ポートが要る。プレイヤーはどちらも持っていない。同じ形が LAN では成立するので、そちらの行にいる |

<Aside type="tip" title="表を読む順番">
自分のプロジェクトに合う行を探すときは、**先にホストを決めます**。サーバを運用するかどうかで、
利用できるリンクとシグナリングがほぼ決まります。
</Aside>

## 信頼モデルとの対応

構成によって、対局結果を信頼できる範囲も変わります。

| 構成 | 信頼モデル |
|---|---|
| solo | standalone。検証する相手がいない |
| lan_pair_or_party | direct_pair。同じ物理ネットワークにいることが唯一の前提 |
| invited_pair_or_party | invited_pair。招待を渡した相手だけが入れる |
| brokered_peer | brokered_pair。control plane が身元を保証する |
| central | central_session。**ランク付きの賭けに値する唯一の行** |
