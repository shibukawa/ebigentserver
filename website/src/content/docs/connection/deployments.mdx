席数・ホスト・リンク・シグナリングを掛け合わせると、組み合わせの数はすぐに数十になる。
だが実際に**相手に届く**のはそのうちの一部だけで、残りは表の上にしか存在しない。

## 届く7つ

### solo

1席、ホストはプロセス内、リンクは pipe すら要らない。agent がそのまま session に着席する。
シグナリングという概念が発生しない唯一の構成。

### local_loopback

2席以上、プレイ中のプロセスがホスト、リンクはプロセス内の `transport/pipe`。

solo との違いは見た目より大きい。solo は agent を session に直接着席させるが、こちらは
**間にトランスポートが挟まる**。エンコード、snapshot と delta の生成、シーケンス番号と ack、
そのすべてがネットワークなしで動く。

そしてこの pipe は、方向ごとに損失・遅延・ジッタ・並べ替えを注入できる。rollback や
lag compensation、delta baseline の復帰経路を、実在しない悪い回線に対して試験するための
装置でもある。ドロップと並べ替えのパターンはシードで再現するが、到着タイミングは実時間の
タイマーに乗るので再現しない。これは意図的にそうなっている。

`ebigent dev` が走らせるのはこの構成だ。

### lan_pair_or_party

2席以上、プレイ中のホスト、リンクローカルアドレス上の WebTransport か QUIC-UDP。
相手を見つけるのは [LAN ディスカバリ](/connection/signaling/)。

ブラウザは UDP ブロードキャストを送れないので、**ネイティブビルド限定**になる。

### invited_pair_or_party

2席以上、プレイ中のホスト、WebRTC。シグナリングは
[手動トークン](/connection/signaling/#手動トークン)——offer と answer をプレイヤー自身が
チャットや掲示板で運ぶ。

静的ファイルだけで成立する。バックエンドは、いかなる意味でも存在しない。

### brokered_peer

2席以上、プレイ中のホスト、WebRTC。ただしシグナリングは control plane が発行する
チケットが担う。サーバはマッチングと認証とシグナリングをやったら、あとはデータに触らない。

### central

2席以上、専用ホスト、WebTransport（届かなければ WebSocket）。サーバはデータ経路にいるので、
プレイヤー間の全交換が2ホップになる。

代わりに、**結果にランクを賭けられる唯一の構成**でもある。

### relayed_peer

2席以上、プレイ中のホスト、TURN リレー経由の WebRTC。サーバはデータ経路にいるが、
それはフォールバックとしてであって、ピア同士が直接届こうとして届かなかった結果でしかない。

制限の厳しいネットワークのための逃げ道。リレーのホップとリレーの帯域という代償は、
それを必要としたセッションだけが払う。

## 届かない3つ

| 構成 | なぜ成立しないか |
|---|---|
| メッシュ | ここでのピアリンクは star 型なので、N ピアは「1ホストと N リンク」であって N² にはならない |
| 主経路としての「dedicated × WebRTC」 | 証明書とルーティング可能な名前を持つホストが NAT 越えから得るものはない。届かないピアの退避路としてなら、それは上の relayed_peer であって別のもの |
| インターネット上の「プレイ中ホスト × WebTransport」 | 証明書と着信ポートが要る。プレイヤーはどちらも持っていない。同じ形が LAN では成立するので、そちらの行にいる |

<Aside type="tip" title="表を読む順番">
自分のプロジェクトがどの行かは、**ホストの列を先に決める**と一意に近く絞れる。
サーバを運用するか、しないか。この一問がリンクとシグナリングをほぼ決めてしまう。
</Aside>

## 信頼モデルとの対応

構成が変わると、結果をどこまで信用してよいかも変わる。

| 構成 | 信頼モデル |
|---|---|
| solo | standalone。検証する相手がいない |
| lan_pair_or_party | direct_pair。同じ物理ネットワークにいることが唯一の前提 |
| invited_pair_or_party | invited_pair。招待を渡した相手だけが入れる |
| brokered_peer | brokered_pair。control plane が身元を保証する |
| central | central_session。**ランク付きの賭けに値する唯一の行** |
