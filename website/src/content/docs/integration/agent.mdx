import { Aside, LinkCard } from '@astrojs/starlight/components';

```go
type Agent[O, A any] interface {
	Joined(slot SlotID)
	Observe(obs O)
	Decide(ctx context.Context) (action A, ok bool)
	Ended(result Result)
}
```

呼ばれる順番は決まっている。`Joined` が一度、最初の `Observe` より前に完了する。以降は
ステップごとに `Observe`、その席が判断する番なら続けて `Decide`。最後に終局局面の
`Observe` が来て、`Ended` がちょうど一度呼ばれる。

**agent が読めるのは視界 `S` だけ**で、世界 `W` には触れない。触れる口がない。

## 2つのペーシング

`Decide` の意味は、セッションの進み方によって変わる。

### ステップペーシング

セッションは `Decide` が返るまで待つ。ボードゲームやターン制がこれ。`ok=false` は
「この操作者はもう続けられない」という申告として扱われる。

`ctx` はセッションが running を離れたときにキャンセルされる。ブロックしている `Decide` は
そこで戻らなければならない。

### リアルタイム非ブロッキング

セッションは待たない。返らなければ、その tick はその席の入力がなかったことになる。

これは事故ではなく宣言された挙動で、[`InputIntake` の設定](/connection/sync/#入力の取り込み方)と
合わせて読むと意味が通る。連続操作なら古い入力は上書きされているし、命令ストリームなら
次の tick に届く。

<Aside type="note" title="Observe はブロックしない">
どちらのモードでも `Observe` の中で長く待ってはいけない。ステップペーシングでセッションが
待っているのは `Decide` の方だ。
</Aside>

## 4つの実装、同じ形

同じインターフェースの裏に何が入るかを並べると、抽象がどれだけ持ちこたえているかが見える。

| 実装 | `Decide` の中身 |
|---|---|
| コンソールの人間 | 標準入力から1行読む |
| スクリプトボット | 視界を見て手を選ぶ（1手読みの greedy など） |
| 蒸留された行動ツリー | [生成された `switch` の決定リスト](/ai/codegen/)を1回通る |
| リプレイ | エピソードログの「この tick に受理された行動」を返す |
| リモートピア | ネットワークから届いた入力を返す |

リプレイが特別扱いされていないことに注目してほしい。記録から着席する `actor:replay-agent` は
**ふつうの agent** で、セッションから見ると人間と区別が付かない。だから記録した対局の再生が
ビット一致するというテストは、再生専用の経路ではなく本番の経路を通っている。

## 席は操作者より長生きする

`concept:player-slot` は「人」ではなく「参加する位置」だ。役割、チーム、能力、そして世界の中で
その席が操るエンティティを持つ。着席する agent はいつでも1つだが、**席の方が先に生まれて
後まで残る**。

この非対称が効いてくる場面がある。プレイヤーが切断したとき、席は空になるが消えはしない。
そこに新しい agent を着席させれば、それが「AI 引き継ぎ」になる。

```go
cfg := netplay.ServerConfig[State, Move]{
	// トランスポートが閉じたか、沈黙が deadline を超えたら呼ばれる
	OnDeparture: func(slot session.SlotID, role, reason string) {
		// ai_takeover: 新しい agent がその席に座る。それだけ
		seatBot(slot)
	},
}
```

引き継ぎのための機構は存在しない。存在しないことを確かめるために、8人対戦に切断・AI引き継ぎ・
不正入力の洪水・入力を送る観戦者を同時に注入するテストが置いてある。セッションは正常に終局し、
正直なクライアントと観戦者は同期を保ち、すべての違反に視界可能な証拠が残る。

## 観戦者

`permission:spectator-receive-only` の席は inbox を持たない。入力の datagram が届いたら
違反として計上し、しきい値で切断する。クライアント側は上りトラフィックがないので、
ack を相乗りさせる相手がおらず、自動的に専用 ack に切り替わる。
