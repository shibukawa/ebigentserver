import { Aside, LinkCard } from '@astrojs/starlight/components';

```go
type Agent[O, A any] interface {
	Joined(slot SlotID)
	Observe(obs O)
	Decide(ctx context.Context) (action A, ok bool)
	Ended(result Result)
}
```

メソッドを呼ぶ順序は決まっています。最初の `Observe` より前に、`Joined` を一度だけ呼びます。
その後はステップごとに `Observe` を呼び、その席が判断する番なら続けて `Decide` を呼びます。
最後に終局局面を `Observe` へ渡し、`Ended` を一度だけ呼びます。

**agent が受け取れるのは視界 `S` だけ**です。世界 `W` へアクセスするメソッドはありません。

## 2つのペーシング

`Decide` の待ち方は、セッションのペーシングによって変わります。

### ステップペーシング

セッションは `Decide` が返るまで待ちます。ボードゲームやターン制ゲームで使うモードです。
`ok=false` は、その操作者が続行できないという申告として扱います。

セッションが running 状態を離れると、`ctx` をキャンセルします。待機中の `Decide` は、
キャンセルを受け取って戻る必要があります。

### リアルタイム非ブロッキング

セッションは `Decide` を待ちません。期限までに返らなければ、その tick にはその席の入力が
なかったものとして進みます。

これはエラーではなく、宣言された動作です。[`InputIntake` の設定](/connection/sync/#入力の取り込み方)と
組み合わせて使います。連続操作では古い入力を新しい入力が置き換え、命令ストリームでは遅れた入力が
次の tick に届きます。

<Aside type="note" title="Observe はブロックしない">
どちらのモードでも、`Observe` で長時間待機してはいけません。ステップペーシングでセッションが
待つのは、`Decide` だけです。
</Aside>

## 4つの実装、同じ形

同じインターフェースを、人間、ボット、リプレイなどの実装で共有します。

| 実装 | `Decide` の中身 |
|---|---|
| コンソールの人間 | 標準入力から1行読む |
| スクリプトボット | 視界を見て手を選ぶ（1手読みの greedy など） |
| 蒸留された行動ツリー | [生成された `switch` の決定リスト](/ai/codegen/)を1回通る |
| リプレイ | エピソードログの「この tick に受理された行動」を返す |
| リモートピア | ネットワークから届いた入力を返す |

記録から着席する `actor:replay-agent` も、**通常の agent** です。セッションから見ると、人間や
ボットと区別できません。そのため、記録した対局がビット単位で一致することを検証するテストも、
再生専用ではなく本番と同じ経路を通ります。

## 席は操作者より長生きする

`concept:player-slot` は人そのものではなく、対局へ参加する位置です。役割、チーム、能力、
その席が世界内で操作するエンティティを持ちます。一つの席に同時に着席できる agent は一つですが、
**席は操作者より先に作られ、操作者が離れたあとも残ります**。

プレイヤーが切断すると、席は空になりますが削除されません。そこへ新しい agent を着席させれば、
同じ席を引き継げます。これが「AI 引き継ぎ」です。

```go
cfg := netplay.ServerConfig[State, Move]{
	// トランスポートが閉じたか、沈黙が deadline を超えたら呼ばれる
	OnDeparture: func(slot session.SlotID, role, reason string) {
		// ai_takeover: 新しい agent がその席に座る。それだけ
		seatBot(slot)
	},
}
```

引き継ぎ専用の機構はありません。8人対戦で切断、AI 引き継ぎ、大量の不正入力、入力を送る観戦者を
同時に発生させるテストでも、新しい agent を着席させる通常の処理を使います。セッションは正常に
終局し、正しいクライアントと観戦者は同期を保ち、すべての違反が証拠として記録されます。

## 観戦者

`permission:spectator-receive-only` の席は inbox を持ちません。入力 datagram が届くと違反として
数え、しきい値を超えた接続を切断します。観戦者は上りトラフィックを送らないため、ack を相乗り
させられません。その場合は、自動的に専用 ack へ切り替えます。

## agent にできないこと

Agent インターフェースが短いのは、agent が使える情報と操作を意図的に制限しているためです。

**世界全体は読めません。** `Observe` に渡される視界だけを読み、`WorldState` への参照は
受け取りません。ゲームが視界へ含めなかった隠し情報は agent 側へ届かないため、安全側の設計に
なります（`rule:sight-content-owned-by-game`）。

**自分を採点できません。** 評価シグナルはセッションが計算し、必要に応じて視界に含めます。
agent 自身が成績を決めると、コーパスの評価が自己申告になってしまいます。

**他の席の操作者を知りません。** 誰が座っているかを問い合わせるメソッドはありません。
`decision:no-ai-game-mode` は、ゲームのルールと agent のどちらにも、操作者の種類で分岐する材料を
渡さないという設計です。

**tick を止められません。** リアルタイムモードでは `Decide` の完了を待ちません。長い思考時間が
必要な agent は、ステップペーシングのセッションで使います。このモードは、開発時の記録生成や
ターン制ゲームに適しています。
