import { Aside, LinkCard } from '@astrojs/starlight/components';

```go
type StageRuleSet[W, A, S any] interface {
	Start(seed uint64) S
	ActingSlots(state *S) []SlotID
	Apply(state *S, slot SlotID, action A)
	Project(state *S, slot SlotID) O
	Evaluate(state *S, slot SlotID) EvaluationSignal
}
```

メソッドは五つだけですが、それぞれにセッションが依存する前提があります。実装時には、
シグネチャだけでなく、次の約束を守る必要があります。

## Start

初期の世界状態を返します。引数の `seed` は、セッションで共有する RNG シードです。

乱数が必要なゲームでは、**この seed からすべての乱数を生成します**。通常は `fixmath.Rand` を
状態へ埋め込みます。すると、乱数列はシミュレーションステップを通じてだけ進み、チェックポイントにも
保存されます。壁時計や、シードされていない生成器は使いません。乱数を使わないゲームでは無視できます。

```go
func (RuleSet) Start(seed uint64) State {
	return State{Rand: fixmath.NewRand(seed), Next: SlotX}
}
```

## ActingSlots

このステップで判断する席を返します。返す順序は問いません。セッションが `SlotID` 順に並べて
コミットします。

**空のスライスは、ゲームにこれ以上の判断がないことを示します**。全席の評価が terminal の場合にだけ
返せます。まだ勝負が付いていない状態で空を返すと、バグとして扱います。

## Apply

検証済みの行動を一つ適用し、状態を進めます。合法性は、その前に `ActionValidator` で確定しています。

**`Apply` は失敗しない前提です**。そのため、エラーを返すシグネチャもありません。判定と適用を
分けることで、rollback では判定だけをすべてのピアで実行できます。判定と適用がどちらも決定的なら、
すべてのピアで同じ結果になります。

<Aside type="caution" title="Apply の中で乱数を引くなら">
状態に埋めた PRNG を使います。`math/rand` のグローバル値や `time.Now()` を使うと、
再生結果がビット単位で一致せず、[ログを検証の証拠として使えなくなります](/ai/episode-log/)。
</Aside>

## Project

指定された席が見てよい視界を組み立てます。

```go
// samples/tictactoe/ttt/ttt.go
func (g RuleSet) Project(s *State, slot session.SlotID) Sight {
	return Sight{
		You:      slot,
		Mark:     mark(slot),
		Board:    s.Board,   // 全員が同じ盤面を見る（global scope）
		NextTurn: s.Next,
		Signal:   g.Evaluate(s, slot),
	}
}
```

三目並べでは、**ゲーム側の判断として**全員に同じ盤面を渡します。framework が全員に同じ視界を
強制しているわけではありません。ダンジョンでは、同じ位置にいても役割ごとに別の view を返します。
`Project` の実装によって、fog of war、視界距離、AI の難易度調整、チート対策を行えます。

視界に何を含めるかは、ゲーム側が決めます。framework は中身を検査しません。

## Evaluate

席ごとの評価シグナルを計算します。セッションが呼び出すため、**agent が自分自身を採点することは
ありません**。

```go
type EvaluationSignal struct {
	Score       int64        // 点数、資源、体力
	Progress    fixmath.F64  // 勝利条件までの距離を [0,1] に正規化
	Evaluation  fixmath.F64  // 局面の評価値。チェスの eval に相当
	RewardDelta fixmath.F64  // 前の判断点からの変化 ← 学習ではこれが効く
	Terminal    Terminal     // win / lose / draw / abandoned
}
```

三目並べでは `Terminal` だけを設定しますが、構造体には最初からすべてのフィールドがあります。
判断ごとの評価がなければ、[蒸留用のコーパスで信用を割り当てられない](/ai/episode-log/)ためです。
エピソードの最終結果だけでは、一つのエピソードに一つのラベルしか付きません。それでは、
良い判断と、結果的に運が良かった判断を区別するには情報が足りません。

数値には固定小数点を使い、浮動小数点をシミュレーションへ入れません。

## Config で組み立てる

```go
cfg := session.Config[State, Move, Sight]{
	ID:         "match-1",
	Slots:      ttt.Slots(),
	RuleSet: ttt.RuleSet{},
	Seed:       42,
	Validator:  ttt.Validator{}, // nil なら全部通る
	Recorder:   writer,          // nil なら記録しない
	Canonical:  ttt.Encode,      // nil ならチェックポイントなし
}
```

任意フィールドがゼロ値の場合は、安全側の既定動作を選びます。最小構成では、ゲームと席だけを
指定すれば動きます。ただし、`RunRealtime` だけは
[`Tuning` の宣言が必須](/connection/sync/)で、既定値を持ちません。
