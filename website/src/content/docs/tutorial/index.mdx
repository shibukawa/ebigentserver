三目並べは、ゲームとして動かすだけなら5分で書けます。難しくなるのは、そのあとです。
たとえば CPU 戦の追加、友達との対戦、CPU の改良です。機能を足すたびに、最初のコードのどこかが
邪魔になります。

このチュートリアルでは、その「邪魔になる瞬間」を順番にたどります。1台のマシンで交互に指すところから
始め、不便が生じた時点で次の道具を導入します。各ステップの冒頭にあるのは、
**前のステップで困ったこと**です。

## ステップ

| ステップ | 内容 | 状態 |
|---|---|---|
| [step 1 — マウス1つで交互に指す](/tutorial/step1/) | ふつうの Ebitengine アプリ。framework を一切使わない | 済 |
| [step 2 — ロビーと LAN 対戦](/tutorial/step2/) | ルールを `StageRuleSet` に。ロビーが相手を待ち、2インスタンスで対人戦 | 済 |
| [step 3 — シンプルなアルゴリズムの CPU を実装する](/tutorial/step3/) | `if` 4本の CPU を人間と同じ席に着ける。その判断が `data:episode-log` に残る | 済 |
| [step 4 — 人の指し手からボットを作る](/tutorial/step4/) | 人の対局記録を整えて蒸留し、自分の写しと対戦する。検証は手書き CPU の再現で行う | 済 |
| [step 5 — シミュレーションで記録を増やし、限界を測る](/tutorial/step5/) | Agent 同士を自動対戦させ、蒸留したボットを動かして結果を測る | 済 |

step 4 が扱うのは、**記録から方策を再構成できるか**です。step 5 では、その入力となる記録も
シミュレーションで作ります。`simulate` がコーパスを作り、`distill` がコーパスから Go を生成し、
生成した `Distilled` Agent をゲームで動かします。

step 3 からは聞き慣れない語が続くため、先に四つだけ説明します。**コーパス**は、あとから読み返せる
対局記録の集まりです。**蒸留**は、その記録から方策を取り出すことです。取り出した結果は、上から
読んで最初に当てはまる規則を採用する **決定リスト**、つまり一つの `switch` になります。
そして**教師**は、記録を残した側を指します。残りの用語は、最初に登場する箇所で説明します。

<LinkCard title="用語の整理" href="/architecture/terms/#記録と方策の語" description="コーパス・述語・語彙・チップ・被覆。記録から方策を作るまでに使う語の一覧。" />

<Aside type="note" title="ボードゲーム編はここで完結する">
step 5 まで実装済みで、三目並べのチュートリアルはそこで完結します。

三目並べはすでに解かれているため、最強の相手を作れます。しかし、その相手は同じ価値を持つ複数の
最適手から、理由なく一つを選びます。step 5 で測るのは**その教師から学ぶ限界**であり、蒸留全般の
限界ではありません。

アクションゲームの敵を「開発者が操作して動きを付け、それを再生する」場合は、前提が大きく異なります。
完璧である必要はなく、教師は探索ではなく人です。そして、人が付けた動き自体が仕様になります。
この使い方は、別のチュートリアルで扱います。
</Aside>

このチュートリアルとは別のサンプルとして管理します。
