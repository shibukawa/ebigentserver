三目並べは、ゲームとしては5分で書ける。だから面白いのは書いたあとの方だ——CPU 戦を足したい、
友達と対戦したい、その CPU をもう少し賢くしたい。そのたびに、5分で書いたコードのどこかが
邪魔になる。

このチュートリアルは、その「邪魔になる瞬間」を順番に踏みに行く。1台のマシンで交互に指す
ところから始めて、不便になった時点で次の道具を入れる。だから各ステップの冒頭には、
**前のステップで困ったこと**が置いてある。

## ステップ

| ステップ | 内容 | 状態 |
|---|---|---|
| [step 1 — マウス1つで交互に指す](/tutorial/step1/) | ふつうの Ebitengine アプリ。framework を一切使わない | 済 |
| [step 2 — ロビーと LAN 対戦](/tutorial/step2/) | ルールを `StageRuleSet` に。ロビーが相手を待ち、2インスタンスで対人戦 | 済 |
| [step 3 — シンプルなアルゴリズムの CPU を実装する](/tutorial/step3/) | `if` 4本の CPU を人間と同じ席に着ける。その判断が `data:episode-log` に残る | 済 |
| [step 4 — 記録からボットを作る](/tutorial/step4/) | 記録から決定リストを蒸留し、生成された Go を座らせる | 済 |
| [step 5 — 相手を回す、そして限界を測る](/tutorial/step5/) | コーパスを広げる。そして完全な教師の限界を測る | 済 |

step 3 から先は聞き慣れない語が続けて出てくるので、先に四つだけ。**コーパス**は
後から読み返せる対局記録の集まり、**蒸留**はその記録から方策を取り出すこと、
**決定リスト**は取り出した結果の形——上から読んで最初に当たった規則を採る、`switch` 一つに
なるもの。そして**教師**は、その記録を残した側である。残りは出てきた場所で説明する。

<LinkCard title="用語の整理" href="/architecture/terms/#記録と方策の語" description="コーパス・述語・語彙・チップ・被覆。記録から方策を作るまでに使う語の一覧。" />

<Aside type="note" title="ボードゲーム編はここで完結する">
step 5 まで実装済みで、三目並べの話はそこで終わる。

三目並べは解けているゲームなので、最強の相手が存在し、その相手は同値な最適手の中から理由なく
1つを選ぶ。step 5 が測っているのは**その限界**であって、蒸留一般の限界ではない。

アクションゲームの敵のように「開発者が操作して動きを付け、それを再生する」使い方は問題の形が
まるで違う——完璧である必要がなく、教師は探索ではなく人で、人が付けた動きはそれ自体が仕様に
なる。そちらは別のチュートリアルで扱う。
</Aside>
