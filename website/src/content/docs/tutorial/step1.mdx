2パッケージに割ったのは作法のためではない。engine を import しないパッケージは
**ウィンドウなしでテストできる**からだ。`main.go` の側にテストを置くと、ディスプレイのない
Linux では ebiten の初期化で落ちる——CI で走らないテストになる。

## ルールの側

```go
// Place takes cell for the side to move and reports whether it happened.
// An illegal cell leaves the state untouched, so a caller may hand it
// any click without checking first.
func (s *State) Place(cell int) bool {
	if !s.Legal(cell) {
		return false
	}
	mark := s.Turn
	s.Board[cell] = mark
	s.Moves++
	if line, won := s.Board.lineFor(mark); won {
		s.Winner, s.Line, s.Over, s.Turn = mark, line, true, Empty
		return true
	}
	if s.Moves == len(s.Board) {
		s.Over, s.Turn = true, Empty
		return true
	}
	s.Turn = mark.Other()
	return true
}
```

不正な手を `Place` 自身が拒み、拒んだときは状態を1バイトも変えない。だから呼ぶ側は、
盤上のどこをクリックされても素通しでよくなる。テストがそれを固定している。

```go
func TestOccupiedCellIsRefusedAndChangesNothing(t *testing.T) {
	s := play(t, 4)
	before := s
	if s.Place(4) {
		t.Fatal("Place on an occupied cell reported success")
	}
	if s != before {
		t.Fatalf("refused move mutated the state:\n got %+v\nwant %+v", s, before)
	}
}
```

## ピクセルがセルになる場所

```go
// cellAt maps a cursor position to a board cell — the one place a pixel
// turns into a move.
func cellAt(x, y int) (int, bool) {
	x, y = x-margin, y-margin
	if x < 0 || y < 0 || x >= boardPx || y >= boardPx {
		return noCell, false
	}
	return (y/cellPx)*3 + x/cellPx, true
}
```

この関数より下は、マウスというものを知らない。`Update` がやるのはその出口を `Place` に渡す
ことだけだ。

```go
func (a *app) Update() error {
	mx, my := ebiten.CursorPosition()

	a.hover = noCell
	if cell, ok := cellAt(mx, my); ok && a.state.Legal(cell) {
		a.hover = cell
	}

	if inpututil.IsMouseButtonJustPressed(ebiten.MouseButtonLeft) {
		if a.state.Over {
			a.state = game.New() // any click starts the next game
		} else if cell, ok := cellAt(mx, my); ok {
			a.state.Place(cell)
		}
	}
	if inpututil.IsKeyJustPressed(ebiten.KeyR) {
		a.state = game.New()
	}
	return nil
}
```

<Aside type="note" title="入力は Update、描画は Draw">
Ebitengine は `Update` を固定レートで呼び、`Draw` は画面のリフレッシュに合わせて呼ぶ。
回数が一致しないので、`Draw` で `IsMouseButtonJustPressed` を読むと入力が抜ける。
[Ebitengine への統合](/integration/ebitengine/)で改めて出てくる話が、ここでもう出ている。
</Aside>

## あとで効く2つの継ぎ目

いま入っている構造のうち、2つだけが後のステップで意味を持つ。

**`cellAt` の出口** — ピクセルがセル番号になったこの地点が、step 2 では `Submit` の引数になる。
その行き先がローカルの inbox なのか1マシン先のソケットなのかを、この行は知らないままでいられる。

**`game` パッケージが engine を知らないこと** — step 2 では `StageRuleSet[S, A, O]` を実装するが、
ルールを移す必要はない。`Project` と `Evaluate` を**足す**だけで済む。

## まだないもの

ボットも、記録も、ネットワークも、シードもない。それどころか `Update` が世界を直接書き換えて
いて、tick という概念すらない。2人が同じマシンにいる限り、それで何も困らない。

困りはじめるのは、3つ目の操作者——CPU——を足そうとした瞬間だ。`Update` の中に
「いま O の番ならボットに考えさせる」と書くこともできるが、その1行が
[最初に禁じた分岐](/overview/#一つの抽象で足りるのか)そのものになる。
